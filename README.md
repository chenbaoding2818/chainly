#### 亮点
1、处理游戏玩家业务逻辑能实现全局无锁，理论上不会有任何并发安全问题。
2、根据玩家数据等级提供不同的数据存储方案
3、在处理多玩家并发请求的情况下，能较好平衡性能与资源消耗问题，使用哈希一致性算法能够玩家在线高峰时，实现处理能力的扩容。
4、提供能够开箱即用的脚手架工具，初始化项目结构，使用户快速开发游戏逻辑。
5、基于事件驱动模型解耦了业务逻辑同时解决了go语言的一个令人厌烦的问题：包的循环引用
6、功能组件化设计，方便扩展和管理

### 八、项目常见问题

网络连接管理

维护海量长连接：客户端不与后端的多个业务服直接连接，而是统一与网关服建立并维持一个TCP/UDP长连接。网关服的核心职责就是高效、稳定地管理数十万甚至上百万的这些连接。

屏蔽内部网络结构：客户端只知道网关的地址，不知道后端有哪些业务服、IP是什么。这极大地增强了安全性，并方便后端服务进行灵活地扩缩容和迁移。

协议处理与消息路由

协议转换：将客户端发来的二进制数据流（通常为自定义协议）进行解包、解码和校验，转换成内部服务间通信的标准格式（如Protobuf、JSON）。反之，也将内部服务的消息打包成客户端能理解的格式发回去。

消息路由：根据消息的类型（例如，是聊天消息还是战斗指令），将请求准确地转发到对应的后端业务服（如聊天服、战斗服）。

安全与过滤

防火墙：进行初步的安全检查，如校验数据包格式合法性、频率限制，抵御Flood攻击等，将恶意流量挡在门外，保护内部脆弱的业务服。

反作弊基础：一些简单的作弊行为（如速度过快、操作频率异常）可以在网关层被检测和过滤。

流量控制与负载均衡

网关可以根据预设的策略和当前后端服务的负载情况，将玩家请求路由到负载较低、健康状况良好的服务实例上。

无状态设计与水平扩展

网关服本身不处理任何业务逻辑，也不存储任何玩家状态数据。这使得它可以非常轻松地进行水平扩展：只需简单地增加网关服实例，并通过负载均衡器（如Nginx, LVS）将玩家连接分摊到这些实例上即可。


登录服
身份认证

验证玩家提交的账号、密码、Token或第三方平台（微信、Steam）凭证的有效性。这是它与用户账户数据库交互完成的。

签发访问令牌

认证成功后，登录服会生成一个有时效性、加密的临时令牌（如JWT）。这个Token是玩家进入游戏世界的“临时通行证”，后续所有请求都必须携带它。

选择游戏世界（区服）与网关

向客户端提供可用的游戏区服列表。

当玩家选择某个区服后，登录服会从该区服的网关集群中，选择一个负载最低的网关实例，将其IP地址和端口返回给客户端。
