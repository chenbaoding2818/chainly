### 一、背景
    这个项目是起源于本人所负责的一个商业项目，翻看了不少github基于golang的关于游戏项目能够开箱即用的构架甚少，所以决定加以修改开源出来，希望能帮助对游戏后端开发感兴趣的同学快速上手。
    本人水平有限，欢迎大家的加入，一起致力于打造一个开箱即用的游戏后端框架，共同进步。
### 二、项目架构介绍
网络通信的数据协议仅支持protobuf，原因很简单，就是流行，其他数据协议比如json因为各种原因逐渐被淘汰。

#### 网络模块架构演进过程

1、有锁架构
2、无锁架构之多玩家共用channel架构
3、无锁架构之Actor模型架构

玩家离线的操作：创建临时的actor处理
1、后台发送邮件通知玩家
2、在线A玩家发送消息给B离线玩家
3、在线A玩家掠夺B离线玩家的物品

#### 亮点
1、处理游戏玩家业务逻辑能实现全局无锁，理论上不会有任何并发安全问题。
2、根据玩家数据等级提供不同的数据存储方案
3、在处理多玩家并发请求的情况下，能较好平衡性能与资源消耗问题，使用哈希一致性算法能够玩家在线高峰时，实现处理能力的扩容。
4、提供能够开箱即用的脚手架工具，初始化项目结构，使用户快速开发游戏逻辑。
5、基于事件驱动模型解耦了业务逻辑同时解决了go语言的一个令人厌烦的问题：包的循环引用
6、功能组件化设计，方便扩展和管理
